# 供给侧定价与分成标准

> 参考:OpenRouter(直通官方价 + 充值手续费)、RapidAPI(佣金抽成)、国内中转站(平台统一倍率)。
> 目标:消除"成本价由供给方自报"带来的作弊/套利空间,把**消费者定价、调度选型、平台盈利**三者解耦。

## 三条标准(必读)

### 标准 1:消费者价 = 平台统一价,不随渠道浮动

消费者通过标准 OpenAI 兼容 API 消费时,统一按 **`ModelRatio`(全局零售倍率)** 计费。

- `ModelRatio` 由平台全局维护,锚定官方公开价(见 `relay/billing/ratio/model.go` 内注释)。
- **任何渠道(含供给方托管渠道)不得影响消费者价格。** 供给方渠道不设独立零售价;消费者看到的价格与渠道无关。
- 现状对照:✅ 已满足——`postConsumeQuota` 用全局 `ModelRatio` 计费,`EffectiveCost` 仅用于成本记账与调度,不参与消费者计费。

### 标准 2:成本价锚定官方基准,供给方不得自由定价

`cost_ratio`(成本倍率)用于**平台与供给方内部结算**及**成本最优调度**,由以下约束管住:

1. **下限**:`cost_ratio >= 1.0`——供给方声称的成本不得低于官方零售基准(`ModelRatio`)。设置低于 1.0 视为**无效/恶意低报**,提交时拒绝。(现状:下限 0.01,过松,收紧到 1.0。)
2. **上限**:`cost_ratio <= 3.0`——供给方声称的成本不得高于官方零售基准的 3 倍,防虚报抬高结算。可配置 `MAX_COST_RATIO` 覆盖。
3. **官方锚定说明**:`ModelRatio` 即"官方零售基准";`cost_ratio=1.0` 表示成本等于官方价,`>1.0` 表示上游有溢价(如官方 key 之外的路由/代理)。
4. **平台可覆盖**:管理员可对单个渠道的 `cost_ratio`/`model_cost_ratio` 强制修正(`IsShared` 渠道留痕)。
5. **触发条件收紧**:只有 `supplier_allowed_channel_types` 白名单内、且通过 `testChannel` 预校验的渠道才能接入(现状已满足)。

> 为什么是"≥1.0":供给方托管的是官方 Key(或等价上游),成本不可能低于官方零售价——这正是防止"供给方报 0.01 抢调度量"的关键。

### 标准 3:平台盈利与调度解耦

- **调度选型**:按 `EffectiveCost` 选成本最低渠道(零售价统一 → 成本最低 = 供给方收益最低 = 平台利润最高)。此逻辑保留。
- **平台盈利**:平台收益来自 **分成 + 流水**,**不依赖"压渠道成本"**:
  - 分成:`platform_ratio`(默认 20%)按公式 `利润 = 零售 − 成本` 抽取(现状已实现)。
  - 说明:当成本被锚定在 `[1.0, 3.0]` 后,平台不会为了高利润而偏爱低报渠道——因为低报已被标准 2 拒绝。
- **套利防线**(标准 3 的延伸,见 `docs/PRODUCT.md`):
  - 供给方既是供给者又是消费者时,其消费按**统一零售价**计费,分成照算——供给方没有套利空间。
  - 调度排除"消费者 token 与渠道 owner 同属一人"的路径(待实现)。

## 实现状态

| 标准 | 现状 | 差距 |
|---|---|---|
| 1 消费者统一价 | ✅ 已满足 | 无 |
| 2 成本价锚定 | ✅ 已实现 | 下限 1.0 / 上限 3.0(可配置 `MAX_COST_RATIO`);成本申报审批管理端 |
| 3 盈利与调度解耦 | ✅ 已实现 | 套利防线(排除自营渠道)+ 信任阶梯 + 对账降权 |

## 实现说明

四个相互配合的机制(对应代码):

1. **可信成本申报**:供给方提交 Key 时 `cost_ratio` 锚定官方价校验(`controller/supplier.go`),落 `cost_decl_status` 待审;管理员经 `/api/cost-decl/` 审批核准/驳回,可顺带指定信任等级。
2. **信任阶梯**:渠道 `trust_level`(1-5)参与调度——路由改为**加权随机**(`model/cache.go weightedPick`),`score = 1/(成本×信任惩罚)`。低信任渠道选中概率低但非零(保证爬坡);成本记账仍用纯成本 `EffectiveCost`,不被信任污染。
3. **套利防线**:`CacheGetRandomSatisfiedChannel` 接收 `excludeOwnerId`,供给方不能消费自己托管的渠道。
4. **对账降权**:结算时用 `used_quota` 周期增量对账(`settlements.used_quota_end` 快照),连续 `settlementTrustDegradeAfter` 个异常周期降 1 级 trust,只降不升。

## 参考

- OpenRouter:直通官方价,平台靠充值手续费 5.5%(最低 $0.80)与 BYOK 超出 5% 盈利。
- RapidAPI:供应商自定价,平台抽 20-25% 流水佣金。
- 国内中转站:消费者价 = 官方标价 × 平台统一倍率;渠道进价内部结算,平台靠倍率差盈利。
