# Neo Matrix 平台规则

> 版本 v0.1 · 生效日期见文末 · 本规则为共享 AI 中转站的运营规范,面向供给方、消费者与平台三方。
> 条款编号便于修订引用;与本仓库 `docs/ARCHITECTURE.md`、`docs/SUPPLIER_PRICING.md` 冲突时,以本规则为准。

## 0. 术语表

| 术语 | 含义 |
|---|---|
| quota | 计量单位,1 美元 = 500,000 quota |
| ModelRatio | 全局零售倍率,锚定官方公开价,消费者统一按此计费 |
| cost_ratio | 成本倍率,供给方申报、相对官方价 `[1.0, 3.0]`,用于内部结算与调度 |
| platform_ratio | 平台抽利润比例,默认 20% |
| trust_level | 渠道信任等级(1-5),影响调度选中概率 |
| settling_balance / withdraw_balance | 结算中余额(锁定)/ 可提现余额 |
| settlements / withdrawals | 结算单 / 提现单,状态机见附录 C |

## 1. 平台定位与角色

- **1.1 平台定位**:共享 AI 中转站,为消费者提供统一 OpenAI 兼容入口(`sk-xxx`),聚合多家供给方托管的 API Key。平台非任何上游模型的官方授权代理或经销商。
- **1.2 三类角色**:
  - **消费者**:按统一零售价预充值消费,与渠道无关。
  - **供给方**:托管自有 Key,按用量分成,可提现。**入驻需经管理员审核**(默认待审核,批准后方可提交 Key)。
  - **平台**:提供调度、计费、结算、风控基础设施,抽取 `platform_ratio`(默认 20%)利润分成。
- **1.3 法律关系**:供给方与平台为"Key 托管 + 分成"关系,非雇佣/合伙/代理;消费者与平台为预付式服务关系。三方均须遵守本规则。
- **1.4 计量**:1 美元 = 500,000 quota;零售价由 `ModelRatio` 全局锚定。

## 2. 供给方准入

- **2.1 申请条件**:平台注册用户,提交入驻申请,经管理员审核通过后方可接入。冻结/封禁用户不可申请。
- **2.2 成本申报**:提交 Key 时申报 `cost_ratio`,必须落在 `[1.0, 3.0]`(上限可配 `MAX_COST_RATIO`),锚定官方零售基准 `ModelRatio`;`model_cost_ratio`(每模型成本)同样须在区间内。低于 1.0 视为恶意低报,直接拒绝。
- **2.3 Key 预校验**:每个 Key 必须通过真实调用预校验(鉴权有效、目标模型可调);OpenAI 系 Key 拉取余额,`balance ≤ 0` 置为禁用。
- **2.4 审核流程**:成本申报先落"待审",管理员核准/驳回,核准时可指定初始信任等级(默认 1)。
- **2.5 BaseURL 约束**:供给方渠道仅允许 https 与公网可达域名;禁止指向内网/本机/云 metadata 地址(SSRF 防护)。
- **2.6 入驻承诺**:Key 为自有或合法授权、申报数据真实、接受周期对账与风控;知悉封号风险由供给方自行承担。

## 3. 供给方行为规范

- **3.1 Key 合规**:仅限托管自有或合法授权的 Key;禁止转托、共享、倒卖他人 Key,禁止隐瞒来源与上游溢价。
- **3.2 禁止套利**:禁止自消费自供给、刻意绕过调度、跨平台搬单、制造虚假链路获取不当收益。系统已排除"消费者与渠道 owner 同人"的调度路径,代理转发仅限管理员。
- **3.3 禁止刷量**:禁止伪造/批量请求、并发空转、刷取结算量或消耗消费者 quota。
- **3.4 禁止虚假申报**:禁止低报/高报 `cost_ratio`/`model_cost_ratio`、篡改模型映射套取更高分成;平台对申报价有最终核定权。
- **3.5 渠道维护义务**:Key 失效、余额不足、上游限流时及时更新或下线,不得长期提交失效 Key 占用调度资源。

## 4. 结算规则

- **4.1 结算周期**:按 `SETTLEMENT_FREQUENCY`(秒)周期聚合消费日志,默认 T+N;周期起止与状态公开可查。
- **4.2 计费口径**:零售额 `total_quota = Σ logs.quota`(统一按 `ModelRatio`,渠道无关);成本额 `cost_quota = Σ logs.cost_quota`;利润 = 零售额 − 成本额。
- **4.3 分成公式**:供给方收益 = 成本 + 利润 × (1 − `platform_ratio`);`platform_quota` = 利润 × `platform_ratio`。`platform_ratio` 默认 20%,变更需公告。
- **4.4 结算中余额**:当期收益先计入 `settling_balance`(锁定、不可提现),确认后转入 `withdraw_balance` 方可提现。
- **4.5 对账与幂等**:结算以 `used_quota` 周期增量对账,不一致标记 `status=3`(对账异常);连续 `N` 个异常周期 `trust_level` 降 1 级(只降不升)。结算按 `UNIQUE(period, channel)` 幂等。
- **4.6 结算异常处置**:对账异常不影响本期入账,但异常渠道降权,连续异常可能停结算/禁用(见第 6 章)。

## 5. 提现规则

- **5.1 提现条件**:`withdraw_balance` 达到最低提现额;完成收款身份绑定;无对账异常、无处罚冻结。结算中余额不满足提现条件。
- **5.2 申请流程**:提交提现金额与收款方式/账号,状态机 0 待审核 → 1 打款中 → 2 已打款 / 3 已驳回。
- **5.3 审核**:管理员在约定时限内审核,核对可提现余额、合规与对账记录;驳回需附 `reason`。
- **5.4 驳回退余额**:驳回后金额自动退回 `withdraw_balance`,可修正后重新申请。
- **5.5 费用与限额**:手续费、单笔/单日限额、汇率与到账时效以当期公示为准。**提现扣减为原子操作**(余额不足拒绝),不会透支。

## 6. 违规与处罚

- **6.1 违规分级**:轻微(提示/警告)→ 一般(降权/暂停分成)→ 严重(冻结/封禁),按影响面、主观故意、造成损失三要素定性。
- **6.2 信任降权**:连续对账异常或轻微违规触发 `trust_level` 下调(1-5,只降不升);调度按信任/成本加权,低信任渠道选中概率低。
- **6.3 冻结与封禁**:对套利/刷量/虚假申报/盗用 Key 等严重违规,冻结提现与分成、停用渠道,必要时永久封禁。
- **6.4 余额处理**:核定的不当收益予以没收并在结算中抵扣;封禁后的剩余合法余额按处罚决定处理。
- **6.5 程序保障**:处罚出具书面决定(依据/措施/期限),供给方可在期限内申诉,重大处罚经复核生效。

## 7. 消费者权益

- **7.1 定价透明**:消费者价 = 平台统一 `ModelRatio`,与渠道/供给方无关;定价表公开并随修订公告。
- **7.2 充值**:预充值 quota,余额仅限本平台消费,不可提现;充值与消费明细均可查询。
- **7.3 退款**:未消费余额按公示政策可申请退充;因平台或上游故障导致的非正常扣费,可申请核查与退补。
- **7.4 服务稳定性**:多供给方冗余调度 + 渠道健康监控 + 失败自动重试;单渠道故障自动跳过切换。
- **7.5 隐私与数据**:消费数据仅用于计费结算与风控,**不向供给方泄露消费者身份信息,不出售对话记录**;日志保存期限公开。

## 8. 责任与免责

- **8.1 上游风险**:上游宕机、限流、价格或政策调整、模型下线属不可控因素,平台尽合理努力但不担保上游可用性。
- **8.2 账号封号风险**:供给方托管 Key 被上游检测或封号,由供给方自行承担;平台可协助排查但不承担损失。
- **8.3 平台责任边界**:平台为技术中转方,不承诺 SLA;因平台自身过失导致的计费/结算错误,由平台负责纠正并补偿。
- **8.4 不可抗力**:自然灾害、网络中断、监管措施导致服务中断或数据损失,双方互不担责,但应尽力减损。
- **8.5 供给方责任**:因供给方 Key 引发上游违规、消费者损失或第三方索赔的,由供给方承担相应责任。

## 9. 争议解决

- **9.1 协商优先**:争议先通过工单/客服协商,平台在约 N 个工作日内响应。
- **9.2 对账异议**:对账单有异议的,可在结算确认前或复核期内申请原始日志查询;逾期未提异议视为认可。
- **9.3 裁决方式**:协商不成的,提交平台所在地有管辖权的人民法院(或约定仲裁机构)解决。
- **9.4 时效**:对账单与处罚决定的异议时效一般为 N 日,逾期不予受理。
- **9.5 中止执行**:争议期间,涉争议余额暂缓结算与提现,待结果确定后执行。

## 10. 附则

- **10.1 版本与生效**:本规则采用"编号 + 版本号 + 生效日期"管理,以站内公示文本为准。
- **10.2 变更机制**:修订需公示期(如 7 天);重大变更(分成比例/手续费/成本倍率区间)公告后按生效日执行,不溯及既往,存量结算周期按旧规。
- **10.3 过渡期**:对存量用户,新规设约 30 天过渡期调整行为。
- **10.4 解释与冲突**:解释与执行细节由平台负责,不得违反法律法规与公平原则。
- **10.5 合规红线(任何情况下不可触碰)**:
  1. **不收集/转卖用户对话数据**(侵犯公民个人信息罪,50 条通信内容即入罪);
  2. **不虚报计费、不做模型掉包**(欺诈);
  3. **不协助规避准入限制**(非法经营);
  4. **数据跨境传输须用户知情同意**(数据安全法)。

## 附录 A:定价速查

- 零售价 = `ModelRatio`(全局),消费者统一。
- 供给方成本价 = `ModelRatio × cost_ratio`,`cost_ratio ∈ [1.0, MAX_COST_RATIO(默认 3.0)]`。
- 示例:某模型 `ModelRatio=2.5`,供给方申报 `cost_ratio=1.0` → 成本倍率 2.5;零售 2.5。利润为 0,供给方拿 2.5,平台 0。

## 附录 D:FAQ

**消费者**
- Q: 我的余额能提现吗? A: 不能,余额仅限平台消费;供给方收益按分成规则提现。
- Q: 上游挂了怎么办? A: 平台自动切换其他渠道;单渠道故障消费者无感。

**供给方**
- Q: 申请后多久能接入? A: 管理员审核通过后即可提交 Key,通常 N 个工作日内。
- Q: 我的 Key 被封了谁负责? A: 由供给方自担(见 8.2),平台协助排查。
- Q: 成本怎么申报? A: 提交 Key 时填 `cost_ratio`/`model_cost_ratio`,管理员核准。
